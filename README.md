# 成品仓地图编辑器原型

仅在本机运行。采用 Vue 3 + Vite + JavaScript ES Modules、Konva.js、Three.js；已提供 C# REST 与 SignalR 适配，但尚未配置真实服务。工程规范见 [Engineering Constitution](docs/WMS_Map_Engineering_Constitution.md)，已完成 Phase 0–10 的前端架构与 Adapter；实际 C# / WMS 服务尚待对接。最新记录见 [Phase 8–10](docs/phase-8-10-validation.md)，配置与后端设计见 [Remote Contract](docs/wms-remote-contract.md)。

## 启动

使用 Node.js 22.12+（本轮验证环境为 24.14.1）。首次运行 `npm install`，然后 `npm run dev`，打开 http://127.0.0.1:5173 。Vue、Konva、Three 等通过 npm 安装，由 Vite 提供或打包，运行时不需要访问 CDN。

`npm run build` 重新生成 `dist/`，`npm run preview` 预览生产构建。`scripts/serve.mjs` 保留为旧式本机静态预览入口，使用前必须先构建。

继续使用原来的 **http://127.0.0.1:5173** 和浏览器配置文件，才能读取原有本机数据。`localhost` 或其他端口属于不同存储来源。开发端口被占用时 Vite 会明确退出，不会自动换端口导致布局看似丢失。

## 已实现

- 两个示例分区，单层、两层、三层实体货架。
- 新增、复制、删除、拖动、0.5 米位置吸附，属性编辑及旋转。
- 平面汇总、指定层显示、货架立面选择、货位编码修改及重复校验。
- 二维和三维共享数据，三维支持旋转、缩放和点选。
- 独立 Runtime 快照与单货位实时更新；正式启动不使用演示库存。
- 撤销重做、当前浏览器本机保存、JSON 导出。

## 文件

- `src/core/`：框架无关的模型、几何、区域、门规则及 JSDoc Contract。
- `src/application/`：命令、选择、会话 Undo/Redo、CAD 工作流、布局生命周期及保存调度。
- `src/components/`、`src/views/`：Vue 工具栏、列表、属性、弹窗及地图容器。
- `src/renderers/konva/`、`src/renderers/three/`：场景、图形交互、命中、预览及渲染缓存。
- `src/infrastructure/`：Repository、Dexie 工作区、安全迁移、偏好存储及 JSON 导出。
- `src/styles/`：原有工作台样式。
- `tests/`、`scripts/check-*.mjs`：Vitest 与保留的独立检查。
- `index.html`：Vite HTML 入口；`src/main.js`：Vue 入口。

`src` 是源码，`dist` 仅为构建输出，禁止手工维护。不要把新业务逻辑写入生成文件。

## 模型约定

坐标以米计，布局 x/y 是地面坐标，Three.js 映射为 x/z；高度对应 Three.js y。货架顺时针旋转角度以度计。货位保存稳定 ID、列、层和独立编码。修改货架名称不自动重命名已有货位。复制货架生成全新货位和空库存。

首次无布局时提供示例几何，不代表真实仓库；布局不再保存库存数量。IndexedDB 是当前浏览器本机工作区，不是服务器备份。JSON 导出可通过布局管理导入并恢复。没有实现真实 WMS 编码绑定、发布审批、碰撞/通道校验、HU 明细和真实堆码位置。三维最多绘制六个示意箱表达有货，准确数量以面板为准。

使用 `.env.example` 配置真实 API、明确的 warehouseCode 与 Hub URL。未配置或请求失败时显示 Runtime 不可用，不生成模拟库存。Layout 与 Runtime 已分离，正式 HU 汇总需由 WMS 确认。

## 检查

`npm run check` 执行全部五个原有检查脚本。`npm test` 使用 Vitest 执行原有检查、Core 边界检查、Vue/编辑器联动和持久化失败测试。`npm run lint` 检查 ESLint，`npm run format:check` 检查 Enterprise Compact 格式，`npm run format` 格式化源码。`npm run build` 验证生产构建。

DOM 测试使用真实 Konva 场景和 Three 几何对象，模拟 Canvas 绘制上下文与 WebGLRenderer；真实 GPU 画面、鼠标命中和轨道控制仍需浏览器验收。基线见 [Phase 0](docs/phase-0-baseline.md)，迁移边界与验收记录见 [Phase 0–3](docs/phase-0-3-validation.md)。

## FG 归属更新

布局 schemaVersion 为 4：货架使用 spaceId（物理空间）和 fgCode（整架业务归属）。当前提供一个共享空间及 FG01/FG02。FG 筛选保留其他货架淡化显示，底部统计跟随筛选；库存与 FG 配色可切换。界面采用淡蓝、淡橙、淡黄，保留有货绿色。旧版浏览器布局读取后将 A/B 映射为 FG01/FG02，保留原坐标、货位身份、编码；旧演示库存被剥离；原先分区坐标重叠时需手工整理。当前使用 IndexedDB 工作区，兼容迁移 library-v1 与 layout-v1/v2/v3；事务写入并读回校验成功后才清理已识别业务键。当前尚未提供多个物理空间编辑和 FG 字典管理。


## 通道、暂存区与边界

左侧物理区域工具支持新增矩形通道、入库暂存区、出库拣货暂存区。点击地图或区域列表选中，拖动移动，右下角手柄缩放，也可在右侧精确输入名称、坐标、宽深和旋转角。仓库边界为不旋转的矩形，通过属性编辑；调整它不移动货架或区域。

区域不归属 FG，筛选 FG 时始终显示。三维同步地面色块、边框及名称，支持点选区域。右侧布局检查提示货架/区域越界，以及货架占用通道或暂存区；使用旋转矩形分离轴检查，边缘相接不算重叠。提示不阻止保存，不包含路径连通性、区域相互重叠、消防或通行宽度合规判断。暂存区目前只有空间布局，不承载 HU 业务。

新增 boundary 和 areas 数据随布局保存、导出及撤销重做。本机存储使用 IndexedDB，兼容迁移旧 v1/v2/v3。旧布局自动补包围边界，不改货架位置，也不自动放置功能区域；全新示例提供三个区域。未来可扩展多边形边界、出入口和通道路线。


## 办公快捷键与 CAD 编辑

二维默认在空白处拖动框选：左向右只选完整包含对象，右向左选择相交对象；Shift 点击切换选择、Shift 框选追加选择。FG 淡化货架和仓库边界不参与多选。选择多个货架或区域后，拖动任意一个可整体移动。按住空格或打开平移按钮拖动地图。

拖动默认吸附 0.5 米网格，并捕捉角点、外包矩形边缘与中心线；辅助线提示对齐。Alt 临时关闭吸附。旋转对象的边缘对齐采用世界坐标外包矩形，角点使用实际旋转后的坐标。

Ctrl+Z 撤销，Ctrl+Shift+Z / Ctrl+Y 重做，Ctrl+S 保存服务器草稿，Ctrl+D 复制，Delete 删除并确认，方向键移动 0.1 米，Shift+方向键移动 1 米，Q/E 绕组合中心旋转 -90/+90 度，F 聚焦，Home 全仓适配，Esc 取消拖动或清除选择，? / F1 打开帮助。输入框保留文本编辑行为；仅全局保存仍生效。Delete 不删除货位或仓库边界。连续按键移动、一次多选拖动或阵列生成各只记录一次撤销。

精确变换支持 X/Y 位移、任意角度和组合中心或自定义世界坐标基点。先旋转再平移。阵列行列总数包含原件，沿世界 X/Y 方向以选择组合的外包矩形加净间距排列，支持画布预览；每次最多新增 200 个对象。复制货架保留 FG 和结构，生成新货位身份与编码，运行态仍独立查询 WMS。三维新增工具只开放查看与聚焦。

cad-geometry.js 是可单独测试的几何和复制逻辑；cad-editor.js 管理选择、拖动、键盘和批量操作。npm run check 包含相关几何、编码、迁移和复制验证。


## 边界门

在编辑仓库边界面板点击新增门。支持门名称、所在边（上/下/左/右）、用途（入库/出库/通用）、起点偏移和门宽。上/下边从左端计算偏移，左/右边从上端计算。门保存在 boundary.doors 中，跟随边界移动，独立于 FG。二维边界按开口断开并显示门标记；三维显示相同开口及 2.4 米高示意门框。门框高度不是现场测量值。

门宽至少 0.5 米，同一边不能重叠；缩小边界造成门越界时拒绝修改。新增、修改和删除门纳入撤销重做、本机保存和 JSON 导出。旧布局没有 doors 字段时按无门处理。点击二维门开口、名称或属性面板的门列表可独立选中门，F 聚焦；三维可点击门框选中。在编辑模式下，二维门可以沿当前边拖动，默认吸附 0.1 米，Alt 临时关闭吸附，越界时限制在边内，与其他门重叠时拒绝此次移动。一次拖动对应一次撤销，Esc 取消拖动；查看模式允许选择但禁止移动。换边和精确定位仍通过门属性修改。门不参与 CAD 框选、阵列或快捷删除，也不包含实际开关状态、门扇动画及路径连通性检查。


## 布局管理与模式

页面默认以查看模式打开：可以筛选、选择、聚焦、查看货位和三维；新增、拖动、缩放对象、位置快捷键、删除和表单修改被锁定。切换编辑模式后启用这些操作。查看模式不是账号权限系统，未来 C# 接入仍需服务端权限校验。

布局管理支持本工具 v1/v2/v3/v4 JSON 文件，最大 5 MB，校验唯一 ID、货位编码、层列完整性、FG/空间、区域、门等。先显示摘要，再确认整体替换，不执行部分合并；不包含运行态库存。空间越界提示不阻止导入。导入/恢复前原子写入当前备份，持久化失败不会替换当前画面。

编辑停止 1.2 秒后自动保存；方向键连续移动结束后才形成一次保存候选。Ctrl+S 先保存本机，再尝试更新服务器草稿；不创建正式版本。切换查看模式和页面离开前尝试落盘；失败会提示导出。常规历史保留最近 20 条，另保留全部迁移备份；每次替换原子保存替换前内容。Repository 将数据写入 Dexie 数据库 wms-map-workspace（版本 2），使用 drafts、history、snapshots、meta。localStorage 仅用于偏好。旧数据经解析、Schema 转换、校验、事务写入及读回验证后才清理；失败保留原文并提示重试，未知键不清理。页面重载恢复最近一次保存，不跨设备同步，也不提供多人并发编辑。

历史恢复先预览，再确认替换；确认时又保留当前版本。导入/恢复会清空本次撤销栈，跨版本恢复使用历史列表。浏览器清理数据会删除本机记录，请定期导出。备份存储失败会保留内存布局并显示失败状态；测试包括存储额度异常的原子性、重复编码拒绝、版本上限。



## 企业草稿与运行态

Local Draft 在 IndexedDB；Server Draft 通过 PUT 保存并检查 draftRevision；PublishedVersion 只能来自 Publish 成功响应。首次对接先读取服务状态，再明确载入服务器草稿建立基线，当前本机布局会先备份。409 不自动合并或覆盖。已发布或身份尚未核验的 LocationCode 在普通编辑器中锁定，货架显示名称仍独立可改。

本机布局、草稿与历史升级为纯布局。数据库旧 cartons 仅可留在 meta 的迁移原文归档中，不用于显示或服务器上传。正式 Runtime 先 GET，订阅 SignalR 后再次 GET 补窗口；序号过旧丢弃、缺口及重连重新同步。未返回的货位显示未知，不当作空位。

## Physical Area / Virtual Location

物理区域可绑定多个 WMS Virtual Location，所有启用绑定均显示。2D 逐行展示，3D 沿较长轴等分视觉区域；不代表真实隔断。绑定进入布局历史，数量仅在独立 Runtime 中汇总。详见 [Area Runtime Patch](docs/phase-8.5-area-runtime-contract.md)。

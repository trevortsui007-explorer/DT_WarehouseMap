# 多地图项目与本地方案

## 操作

1. 打开「布局管理」，原地图自动归入“现状方案”。顶部显示项目名／当前方案名。
2. 展开「新建空白地图」，填写名称和边界宽深（默认 30 × 20 米）。创建成功进入二维查看模式，切到编辑模式后开始绘制；新地图不生成演示对象或库存。
3. 在「复制为新方案」输入如“调整方案 A”。当前工作先保存，再复制布局、底图和实测。对象身份保留，实测统一待复核，旧 Undo、历史、Runtime 和服务器修订不复制。
4. 在项目下拉框选择项目，再点对应方案的「打开」。切换先保存当前方案并校验目标，失败留在原工作。每份方案的自动保存、历史、底图、实测和恢复包独立；会话 Undo 在切换后清空。
5. 可重命名项目和当前方案，名称不改变 Layout 身份或货位编码。刷新恢复上次成功打开方案。
6. 导出项目备份保存当前方案全部资料（不含项目的其他方案）。导入可选“作为新项目打开”或“替换当前方案”；后者保留原身份校验及替换前恢复包。

## 存储和接口

Layout Schema 仍为 6；Dexie 数据库版本 4 保留全部既有表，增加 projects（projectId）和 workspaces（workspaceId，projectId，updatedAt）。旧持久化表中的 layoutId 分区列继续保留，但代表本地 workspaceId；真实业务布局身份在 draft.data 内，两者不得混用。

目录 Repository 提供 list/info/last/remember/createMap/copy/renameProject/renameWorkspace/importProject；每个编辑会话持有按 workspaceId 固定绑定的 Repository。旧回调即使迟到，也只能访问旧分区；会话 epoch 防止迟到 UI 更新，新会话重建选择、Undo 和 Runtime。

旧 main 工作区通过事务收纳进“现状方案”：校验草稿、历史、资源及恢复包，迁移资源归属并读回验证，最后写标记。失败不写标记，允许再次载入。原来按业务 layoutId 存储的资源副本保留，不删除未知数据。数据库结构升级不清库。

项目备份格式版本 2 增加 names.projectName / names.schemeName，仅携带当前方案。旧格式 1 继续支持。新建导入项目保留原 Layout 和对象身份，但分配新的本地 projectId/workspaceId，且不继承云端权限；名字不用于 WMS 身份识别。

## 云端边界

新项目和复制方案仅本地保存，Ctrl+S 只保存本地方案，不上传服务器、不创建发布版本。原工作区保留已有显式云端操作；服务器草稿不作为共用正式地图。只有后端确认发布的版本属于正式地图。本轮未增加本地方案的发布或远程绑定流程。

未关联仓库的新地图显示“未关联运行态”；关联仓库的方案通过独立快照/实时会话读取数据，不复制上一份方案的运行态。

## 人工验收

- 新建仓库，添加房间／货架，复制 A/B；分别修改后切回检查互不影响。
- 上传底图、保存实测，再复制：底图比例保留，实测待复核。不同方案调整底图或应用实测后互不影响。
- 切换后二维居中、查看模式、无选择、Undo 清空；布局历史仍属于各自方案。
- 刷新恢复最后打开方案；项目及方案名称可编辑。
- 导出格式 2，作为新项目导入；旧格式 1 仍可导入；替换失败或事务失败不丢当前工作。
- 原工作区可见既有云端入口，新方案只显示本地保存，不因全局 API 配置自动写云端。

本机保存依赖当前浏览器存储；重要方案请分别导出备份。本轮不提供删除、方案合并、跨项目复制或整项目批量打包。
